# Balda (React) — project context

The "Balda" word game (human vs computer) on **Vite + React + TypeScript**. A port of the ES5 original (`../balda`) preserving game logic and behavior 1:1. No state management libraries — `useReducer`. Dependencies: `react`, `react-dom`, `vite`, `@vitejs/plugin-react`, `typescript` + types. Node.js ≥ 20.19.

Beyond the original: the footer is a single row of four icon buttons — **new game** (opens a modal with the **game language** (RUS | ENG — each with its own alphabet, dictionary and starting word) and the **bot difficulty** (легко/средне/сложно — easy plays words of exactly 4 letters, and the nearest shorter length when the board offers none of the target length; medium the longest word of at most 5 letters; both ease off by one letter (to 3 and 4) when a cap-length word would put the computer's score above the player's — the player already losing included; hard the longest word with no length limit at all) and the start button), **history**, **help** and **settings** (a modal with the board themes).

## Running and commands

```bash
npm install
npm run dev      # dev server
npm run build    # tsc --noEmit + vite build → dist/
npm run preview  # production preview
npm run check    # node logic-check script (compiles scripts/check.ts into .tmp-check and runs it)
```

There is no test framework — correctness of the logic is verified by `npm run check` and the manual checklist in "Browser testing" below.

## Browser testing

GUI changes (layout, highlights, statuses) can additionally be verified in a real browser. **Never start it on your own — ask the user first and wait for an explicit go-ahead.** When the user approves, offer to switch this work to the cheap model (**GLM-5-Turbo**, a subagent or a separate session) instead of the main model: it is routine, screenshot-heavy work. Run it on the main model only if the user declines the switch.

1. `npm run dev` in the background; open the printed URL (the port shifts from 5173 when busy; the base path is `/balda-react/`).
2. Drive the page with the session's browser automation. Stable hooks: `.board .cell` (25 buttons in board order), `.keyboard`, `.turn`, `.result`, `.error`, `.words-progress`.
3. One full round. The starting word is random — first read the middle row (`.board .cell` 10–14), then play any word that adds one letter to it (an invalid try keeps the path, so wording out is cheap; validation errors are part of what you check anyway). When the middle row happens to be «балда»: click the empty cell above the second «а» (`.nth(6)`) → enter «ф» on the keyboard → press cell 6 and drag the pointer through cells 11, 12, 13, 14 (**including the added-letter cell** in the path) → release — the release submits the word (gives «фалда»; without the letter cell the word stays «алда» and submit fails). Check:
   - the turn badge flips «Ваш ход» → «Думаю…» (colored by side, ~0.7 s at least — `BOT_TURN_DELAY_MS`) → «Ваш ход»;
   - path cells carry `.cell-num` numbers 1..n while building;
   - after the reply `.result` shows the bot's move — «Бот:», then the word (bold, `.status-word`) and its points (`.word-len`, e.g. +5) set off by style instead of quotes/parentheses — and the bot's cells carry `.bot`/`.bot-new` with the word's order numbers in `.cell-num` (same rendering as the player's own track) — for ~3 s only (`BOT_MOVE_HIGHLIGHT_MS` in `App.tsx`); assert the classes while the badge is back at «Ваш ход», then again after ~3.5 s (must be gone);
   - `.words-progress` grows («Слово 3 из 21» after this round).
4. Worth an occasional pass: a validation error keeps the path (the error shows as a toast fixed to the top of the screen that hides itself after ~3 s — it takes no layout space); «Отмена»/Escape rolls the move back; a plain click on a filled cell in the word phase does nothing — except on the added-letter cell: the click reopens the keyboard, a changed letter replaces the pending one and resets the path, and a tap on a filled cell / Escape / the panel's ✕ closes it (a tap on an empty cell that cannot take the letter leaves the panel open); a tap on another legal empty cell (one that adjoins letters once the pending letter is lifted) moves the added letter there and reopens the keyboard anchored at its new cell — the letter can be changed or kept, the word is drawn anew, no «Отмена» needed; the word itself is drawn by dragging only. In the English game, tapping a word in a score list or the bot's word in the status line opens the translation popup (`.word-card`: the word with the «сущ.» marker, the IPA, the Russian translations, the Yandex link) — ✕, a backdrop click and Escape close it; russian words keep their direct gramota.ru tab. At a phone viewport (≤560px) the keyboard spans the full screen width, pinned to the viewport edges (three QWERTY rows of equal-width keys, clamped above the footer); the footer is pinned to the bottom edge as one row of four icon buttons — new game, history, help, settings (the plus opens the new-game modal: language, difficulty, the start button; the gear the theme cards); the page itself does not scroll — the score word lists scroll inside their columns with no visible scrollbar.
5. The saved game (`state/persist.ts`): after a played word, reload the page — the board, both score lists and `.words-progress` must come back exactly as they were, and the badge must read «Ваш ход» (never «Думаю…»: a saved `bot` phase restores as `idle`). Reloading mid-move — the letter placed, the path half-drawn — must come back with that move rolled back, not half-applied. «Заново» and a language switch clear the slot, so a reload right after either starts a fresh game.
6. Zoom is locked (a phone viewport or a touch-emulating device): a pinch and a double tap on the board must not scale the page, while taps, drags and the score-list scrolling keep working.
7. Drag selection (word phase): after placing the letter, press a path cell and drag it through the word — the `.cell-num` numbers and `.select` highlights follow the pointer, dragging back over the path unwinds it, and releasing the pointer submits the word (the badge flips to the computer; a 1-cell path is kept instead of erroring). A press released on the same cell without entering another one is a plain click and does nothing. In the word/letter phases «Отмена» sits on the same controls row as «Заново».

## Architecture

- **State is the source of truth, not the DOM**: the board is `board: string[25]` (25 cells, `''` = empty) in `useReducer`; cells are `<button class="cell">`. The dictionary is bundled as an ES module; a prefix tree (trie) per language is built on load.
- **A state machine** instead of the original's attaching of listeners: `phase: 'idle' | 'letter' | 'word' | 'bot' | 'over'` — the game starts immediately in `idle` (the original's «Старт»/menu screen is dropped). Cycle: `idle` (choosing an empty cell that adjoins existing letters) → `letter` (the letter keyboard floats at the selected cell) → `word` (a single drag over adjacent cells builds the `track`, releasing the pointer submits it — `SUBMIT_MOVE`; a click on the added letter's cell reopens the keyboard to change the letter, a click on another legal spot moves the letter there with the keyboard reopening at its new cell) → `bot` (an effect in App calls `findBestMove` via `setTimeout`, held for `BOT_TURN_DELAY_MS` ~0.7 s — an artificial pause so the badge's flip to «Думаю…» is readable) → `idle`; with 21 words in `usedWords` — `over` (EndPanel instead of `alert()`).
- **Bot's turn**: `useEffect` in App when `phase === 'bot'`; the result arrives as the `BOT_MOVED` action (`null` = no move, skip).
- **Physical keyboard**: a letter (ё → е) enters/replaces the pending one while the letter keyboard is open (the `letter` phase, or the `word` phase with the panel reopened on the added letter); `Escape` closes the open keyboard, cancels the move, closes the rules modal, or closes the word popup when it is open. There is no Enter/Backspace handling — the word is submitted by the drag release.
- **Drag word selection** (the `word` phase only) — the single way a word is entered: press a filled cell and drag through adjacent cells (`useWordDrag` in `Board.tsx`; pointer events, so mouse/pen/touch all work), releasing submits the word (a path of a single cell is kept, not erroring). Dragging back over the path unwinds it; a drag begun on a path cell rewinds to it, and one begun from an unrelated cell replaces the path — the fast redo after a validation error. The semantics live in the `DRAG_START`/`DRAG_CELL` reducer actions; a press that never enters another cell is a plain click, and plain clicks in the word phase only work the letter keyboard and the letter's cell (`CLICK_CELL` chooses the letter cell in `idle`, re-targets it or dismisses the panel in `letter`, and in `word` reopens the panel on the added letter, moves the letter to another legal spot with the keyboard following, or closes the panel (a tap on an empty cell that cannot take the letter does nothing — the panel stays). `.board` carries the `word` class in the word phase for `touch-action: none` (otherwise a touch drag is stolen by scrolling); `user-select: none` keeps text selection out of the gesture.
- **The game survives leaving the app** (`state/persist.ts`): the state is written to localStorage under `balda-game` after every action (an effect in App keyed on the whole `state` object) and read back by `initGame` as the reducer's initial state — the phone's Back button closes an installed PWA outright, so without this a game was lost to one stray swipe. The snapshot is deliberately partial: only `lang`, `board`, the three word lists, the played words' tracks (`tracks`: word → board path, the starting word's being the middle row — score-list taps lay a word's track back on the board, see 13) and an `over` flag. The move in progress is **rolled back** into it the way `CANCEL_MOVE` does (the stored board is `boardBackup` when there is one), and the transient fields (`track`, `numChar`, `selectedCell`, `error`, `status`, `lastBotMove`) are rebuilt empty — a drag interrupted by the app closing is not a resumable state. The `bot` phase is stored as `idle`: replaying the computer's answer on restore would answer a board it never saw, so it forfeits that one turn. A game still on its starting word is not stored (and clears the slot), so the random starting word of a fresh launch is never pinned. The snapshot is versioned (`VERSION`, bump on any shape change) and shape-checked on read; anything corrupt, foreign-versioned or of the wrong board size is dropped rather than repaired. A save of the *other* language is kept, not cleared — switching back should not have had to destroy it. `scripts/check.ts` covers the round trip, the rollback, the phase normalization and each rejection path.
- **No zoom on phones**: the app is a fixed shell with a drag surface, and a pinch or double-tap zoom leaves it scaled with no page to scroll back. Three layers, because no single one covers every browser: the viewport meta (`maximum-scale=1, user-scalable=no`) for Android and the installed standalone app; `touch-action: manipulation` on `body` plus `text-size-adjust: 100%` on `html` (iOS otherwise rescales text on rotation); and `src/noZoom.ts` for iOS Safari in a tab, which has ignored the viewport flags since iOS 10 — it cancels the WebKit `gesture*` events, the second `touchend` of a double tap, any `touchstart` with more than one finger, and ctrl/⌘+wheel. All its listeners are `passive: false`, or `preventDefault` would be a no-op. Cancelling `touchend` does not suppress the click after a single tap, so buttons keep working. `.board.word` still narrows `touch-action` to `none` while the path is drawn.
- **Board themes**: the palette is a set of CSS custom properties; `data-theme` on `<html>` (set from App, persisted in localStorage; `index.html` hardcodes `neon` for the first paint) switches it. The same effect points every `meta[name="theme-color"]` tag at the theme's `chrome` color (`chromeColorFor` in `theme.ts`) — the OS chrome above the page (the installed standalone app's status bar on Android, the desktop tab bar) follows the theme switcher live; the tags in `index.html` and the manifest's `theme_color` are the launch color only. The meta ships as two tags with `media="(prefers-color-scheme: light/dark)"` (both carry the same live color): Chrome picks the tag matching the system scheme, and in the installed standalone app it ignores a scheme-less tag outright while Android's dark mode is on (Chromium 40634649 — the bar then falls back to the manifest's static color). A stubborn standalone build may still keep the baked manifest color whatever the page does — that is the platform's limit; the launch color is what shows then. Picker order: wood, night, neon, paper; default: `neon` (`DEFAULT_THEME`); empty cells are styled via `.cell:empty`. A saved id that is no longer in `THEMES` falls back to the default. The ThemePicker swatch cards live in the settings modal (the footer's gear button, see 19).
- **Game language**: `GameState.lang` (set at `freshGame(lang)`, kept by a plain `NEW_GAME`) carries the alphabet, dictionary and starting word in use (`game/lang.ts`). The language is picked in the new-game modal (the footer's plus button): the selection applies — and restarts the game — when the modal's start button is pressed, which arms to «Точно?» over a game in progress (see 19). All rendered texts come from `TEXTS[lang]` (`i18n.ts`); validation errors and bot statuses are stored in the state as structured codes (`GameError`, `Status`) and localized on render, so no game text is hardcoded in components.
- **Bot difficulty**: `findBestMove` records every word the bot could play (deduplicated by word) and `pickMove` chooses: easy — a random 4-letter word (the nearest shorter length when the board offers none of the target length); medium — the longest word of at most 5 letters; hard — the longest, uncapped (the original's behavior, first found among equals) — App passes both sides' scores to `findBestMove` and the two capped levels ease off by one letter with them (easy 4 → 3, medium 5 → 4) when a cap-length word would put the computer's score above the player's (the player already losing included, as any word then grows the computer's lead). Hard has no length limit and no easing: it always plays the longest word it found. When no found word fits a level's cap, the shortest one is played. Switching difficulty (in the new-game modal, where the choice applies at once — no restart) takes effect from the bot's next turn. Default: `medium` (`DEFAULT_DIFFICULTY`).

### Game model (as in the original)

- The starting word in the middle row (cells 10–14) is drawn at random from the language's 5-letter dictionary words (`startWordFor` in `game/lang.ts`, a different word each game — the original always used "балда"); it is the first entry of `usedWords`; points = the total length of composed words (1 per letter); the game lasts until 21 words are in `usedWords`. `freshGame(lang, startWord?)` accepts a forced word — used by `scripts/check.ts` to keep its reference positions deterministic.
- Submit validation is a port of `events.validate` with the same checks in the same order; the error texts live in `i18n.ts` as the Russian renderings of the codes `noAddedLetter` («Слово должно содержать добавленную букву»), `wordUsed` («Слово "…" уже использовано»), `wordNotFound` («Слово "…" не найдено»), `addLetter` («Добавьте букву»), `chooseWord` («Выберите слово»).
- Dictionary: a prefix tree (trie) — a node per prefix, children indexed by the letter's position in the language's alphabet; `findWord`/`hasPrefix` are single root-to-node walks, and the move search (`finder.ts`) carries the current node through its recursion, stepping the tree one letter per board cell instead of re-hashing the whole prefix and binary-searching it at every step (a branch dies the moment no word continues the prefix; a childless node means the prefix cannot grow). Words of any length enter the tree — the original's 10-letter cap is dropped; a board path is physically bounded by the 25 cells.

## Conventions

- TypeScript strict, ES modules.
- **Language: files (code, docs), code comments and commit messages — in English.** Game-facing texts live in `src/i18n.ts` — the Russian set preserves the original's wording (parity), the English set is its translation; do not hardcode game texts in components. Dictionaries stay in their own languages by definition.
- **Commit message format**: a short summary on the first line, then a blank line, then the body describing the change. The summary stands on its own — no trailing period, no scope prefix; the body carries the reasoning, the details and the numbers, wrapped as prose rather than crammed into the first line.
- **No tool trailer in commit messages.** A commit message (and a PR description) ends with its own text — never with `Co-Authored-By: Claude …`, `🤖 Generated with [Claude Code]…` or any other model/agent attribution line.
- **No automatic commits.** A commit is made only when the user explicitly asks for one — finishing a task, passing a build or a check is never a reason to commit on its own. Leave the changes in the working tree for the user to review and commit themselves.
- UTF-8 encoding; the dictionaries in `src/game/dictionary*.ts` are encoding-critical (`<meta charset="UTF-8">` is declared in `index.html`).
- The algorithms in `dic.ts` / `finder.ts` are ported from the original; do not change their structure without need (the difficulty selection in `pickMove` and the all-moves collection are deliberate extensions; so is the trie that replaced the original's hash arrays as the lookup structure — the found words, their order and the pruning semantics are unchanged).

## Typical tasks

- **Change game rules/logic** — `src/state/gameReducer.ts` (and `src/state/types.ts`).
- **Speed up the move search** — `src/game/finder.ts` (the search) and `src/game/dic.ts` (word checks).
- **Replace/extend the dictionary** — only the contents of the `dictionary` array: Russian in `src/game/dictionary.ts` (words of any length take part in the search, no "ё", lowercase), English in `src/game/dictionary-en.ts` (common noun lemmas, a–z only; the regeneration command is in its header). The trie is built per language on first use. After changing the English dictionary, regenerate its translation data too: `node scripts/translate-en.mjs`.
- **Change UI texts / add a translation** — `src/i18n.ts` only (both languages side by side).
- **Tune the difficulty levels** — `pickMove` in `src/game/finder.ts`.
- **UI/layout** — `src/components/` + `src/styles/index.css`.
- **Add/recolor a board theme** — a `[data-theme='…']` variable block in `src/styles/index.css` + an entry in `THEMES` (`src/theme.ts`, including its `chrome` status-bar color) + its names in `i18n.ts`; no other places.

## Known fixes relative to the original

1. "Отмена" resets `numChar` (in the original the highlight stayed and caused a false validation error).
2. Neighbor check `i > 5` → `i >= 5` (cell 5 could not see its top neighbor) — `helpers.ts`, `finder.ts`.
3. No move for the bot — the turn is skipped (the original crashed).
4. The hidden `#time` and `#emulator` ("Help") were not ported.
5. UI cleanups: the «Старт» screen is dropped (the game starts immediately); there is no submit button at all — the drag release submits the word, so the word-phase controls are a single row of small secondary buttons: «Заново» on the left with a two-tap confirmation («Точно?», 3 s) and «Отмена» on the right (in the `letter`/`word` phases) — a stray tap can no longer destroy the game; the letter keyboard floats anchored to the selected cell (below it in the top half of the board, above in the bottom half — `Keyboard.tsx` measures the cell and positions the panel in `.board-wrap`) instead of the original's top-of-screen overlay, so it opens where the click/tap happened and neither the cursor nor the thumb travels far (the board stays interactive around it, a tap on another empty cell moves the pending letter there — the panel follows — and a tap on the selected cell itself dismisses it); on phone-width screens (≤560px) the panel is pinned to the viewport edges and spans the full screen width; the letters sit in three QWERTY/ЙЦУКЕН rows of equal-width keys (`keyboardFor` in `game/lang.ts` — the same letters as the alphabet, in typing order) at every screen size, not a wrapped cloud; the footer is a single row of four icon buttons, each opening its modal (see 19).
6. Error recovery (the original cleared the whole path): a validation error keeps the `track`, and a new drag reworks it — dragging back unwinds the path, a drag from an unrelated cell replaces it. There is no cell-by-cell path editing: no click-to-pop, no Backspace — but the added letter itself can be reworked: a click on its cell in the word phase reopens the floating keyboard, and the picked letter replaces the pending one (a changed letter resets the drawn track — the word is drawn anew; picking the same letter keeps it, and the stale error clears); a click on another legal spot — an empty cell that still adjoins letters once the letter is lifted, checked against the board before the letter so the new cell cannot end up isolated — moves the letter there outright and reopens the keyboard at its new cell (the drawn track resets with the move — the word is drawn anew; a different pick replaces the letter, the same one keeps it, and a begun drag closes the panel so the word can be dragged at once). While the reopened panel is up, a tap on a legal spot moves the letter and the panel follows it, a tap on a filled cell closes the panel, and a tap on an empty cell that cannot take the letter does nothing — the panel stays; a begun drag, the panel's quiet ✕ (borderless, dimmed — `.keyboard-close`) or `Escape` closes the reopened panel leaving the letter where it stands — `Escape` cancels the move only when the keyboard is closed.
7. Additions beyond the original: the language switcher (RUS | ENG — a second alphabet/dictionary/starting word, all texts localized via `i18n.ts`; switching restarts the game, two-tap-confirmed when in progress), the difficulty switcher (easy plays words of exactly 4 letters — the nearest shorter length when the board offers none; medium the longest word of at most 5 letters; both one letter shorter when the word would put the computer's score above the player's; hard the longest word with no length limit; when nothing fits the cap, the shortest word) and the random starting word (a random 5-letter dictionary word each game; the original always started with "балда").
8. An empty cell with no letters around it cannot be chosen for the new letter — in `idle` and in the `letter` re-target (`hasFilledNeighbor` in `gameReducer.ts`); such cells are dimmed and unclickable in the choosing phases (`disabled` in `Board.tsx`). The original allowed any empty cell, and a letter placed in isolation could enter no word, dead-ending the move until «Отмена».
9. The Russian dictionary is replaced: ~50,900 common nouns from Harrix/Russian-Nouns (MIT; nouns/lemmas only, like the original's list) instead of the original's ~16,000-word `out3.js` list. Same filtering rules as the English dictionary: lowercase, "ё" → "е", length 2 and up (the original capped words at 10 letters — both dictionaries now ship words of any length); the regeneration command is in the file header.
10. Drag word selection (addition, and the only word input): the path is drawn with one pointer trajectory instead of cell-by-cell clicks — press + drag builds it live (highlight, numbers, the word in the status bar), dragging back unwinds it, and releasing submits the word (word-search style; a 1-cell path is kept rather than erroring). Implemented as the `DRAG_START`/`DRAG_CELL` reducer actions plus the `useWordDrag` gesture hook in `Board.tsx` — click vs drag is decided by whether the pointer ever entered another cell; plain clicks in the word phase do nothing.
11. The lookup structure is replaced: a prefix tree (trie) instead of the original's base-32 hash arrays with binary search (`dic.ts`); the move search steps the tree along the path (`finder.ts`). Same found words in the same order (verified by identical games in `npm run check`), roughly 5–9× faster on filled boards. Two strictness improvements over the old hashing: a word containing a letter outside the alphabet used to hash as if the letter were absent (so `findWord("аё…")` could alias a real word) — now it is simply not found; and `hasPrefix` of a single letter that starts no dictionary word used to return true — now false (no caller relied on either quirk).
12. The rules are a modal (`RulesModal.tsx`, opened by the footer "?" button, closed by ✕ / a backdrop click / Escape): a brief summary in the current language plus a link to the Russian Wikipedia article — the Russian wiki in both game languages (`RULES_WIKI_URL` in `i18n.ts`). The validation error is a toast: a pill fixed to the top of the screen (`pointer-events: none`) that hides itself after ~3 s (`ERROR_TOAST_MS` in `StatusBar.tsx`) — it takes no layout space, so the status bar is a single row with the board just under it; the error itself still lives in the game state until the player's next action clears it, as before.
13. The words in the score lists are tappable (new tab for the outbound ones): russian words open in gramota.ru's «Проверка слова» over the толковые словари, english ones open the translation popup (see 17) which carries the same Yandex Translate (en→ru) link the words used to follow directly (`wordUrl` in `ScorePanel.tsx`; the target follows the game language — `GameState.lang` — not the UI language). The bot's word in the status line behaves the same (StatusBar). So does the starting word while no word has been played yet: it fills the otherwise-empty status line (`startWord` in StatusBar, styled by the neutral `.status-start` — the word belongs to neither side; App passes it while `usedWords` holds only the start word) — on the board it is just letters and no score column owns it, so the line is its only lookup/translation entry point. Every such tap also lays the word's saved track back on the board: each played word carries its path in `state.tracks` (`GameState.tracks`, word → cells in spelling order — the player's words at `SUBMIT_MOVE`, the computer's at `BOT_MOVED`, the starting word's being the middle row), and App's `shownTrack` puts it on the cells as a muted «history» highlight (`.cell.shown` — the dashed `--cell-selected-*` look, first in Cell's class order so every live highlight wins where they overlap) with the word's letter order numbers in `.cell-num`; the path stays on the board after the popup closes, and the next game action clears it (an effect keyed on the state object). The lists render newest-first, and each word's letter count is a styled `.word-len` span, not parenthesized text; the count sits on the word's baseline (the bottom edge — explicit `vertical-align: baseline`), while the word and its metadata ride in one `.word-inner` inline line that the phone rows center vertically in their 36px chip (baseline-aligning the flex items themselves would pin the line to the chip's top). An english word is followed by its IPA transcription in the same quiet metadata tone (`WordIpa`/`.word-tr` in ScorePanel, shared with the status line) at every width and in every place a word shows: the score rows of both columns, the bot's word in the status line and the starting word there — on the phone a row whose word plus IPA does not fit the half-screen column simply wraps to a second line inside its chip. Where a count follows the transcription (the english score rows, the bot's «+n» in the status line), the two ride in one non-breaking `.word-meta` group: the wrap then falls between the word and its metadata, and the second line carries the transcription with the count — a count alone on the wrapped line read as a stray digit.
14. The English dictionary is nouns-only (parity with the Russian one): WordNet 3.1 noun lemmas kept if present in any of three common-word lists (`popular.txt`, OpenSubtitles `en_50k`, google-10000-english) — ~15,300 common noun lemmas; `popular.txt` as the sole filter (the first cut) dropped everyday nouns WordNet knows (soundtrack, wifi, internet, email, tv, pc, dna, fbi). Proper nouns and abbreviations are dropped by their occurrences' case in `data.noun`: a lemma that never appears lowercase is not a plain word — a name (Abraham, Aberdeen, McDonald) or an abbreviation (bk, ghz, gsr, jfk) — and is kept only on the KEEP whitelist of widely known abbreviations (atm, dna, fbi, gps, kgb, pc, wifi, www — 55 entries, inline in the header's regeneration command); a DROP blocklist removes the abbreviation- and symbol-junk that slipped through lowercase occurrences in WordNet glosses (kg, lb, mm, ph, hr, db) and obscure letter-words (aa, ut, os) — mostly two-letter ones. Lemma-level parts of speech, so words with a noun sense stay (run, walk, jump, running). WordNet also lists plurals that lexicalized their own sense as lemmas — regular ones (colors «знамёна», papers «документы», words «перепалка») and four irregular ones (men, teeth, oxen, brethren) — and those are dropped by a morphology check in the regeneration command: a word ending in -s/-es/-ies/-ves whose singular is also in the dictionary is an inflected form, and the rules promise base forms. The PLURAL_KEEP whitelist (22 entries, inline there too) keeps the words whose -s form is the base one: plural-form everyday nouns (clothes, trousers, jeans, glasses, shorts, pants, means, crossroads, woods), -ics sciences (physics, optics, ethics, acoustics, aesthetics, dynamics, mechanics, graphics, statistics, tactics) and three strip-s false positives that are not plurals at all (canvass, pass, puss); pluralia tantum whose singular is not in the dictionary (scissors, credentials, jitters) are not caught by the check and stay.
15. The app-shell layout (≤560px, or ≤1024px held in portrait — the media query near the end of `styles/index.css`) covers phones and upright tablets: the footer is pinned to the screen's bottom edge as one centered row of four icon buttons (see 19), translucent over the page with a blur (`--footer-bg`/`--footer-border` per theme); the page itself never scrolls — `body` is a `100dvh` flex column with `overflow: hidden`, and what scrolls is the score word lists, inside their columns and with the scrollbar hidden (`scrollbar-width: none` + `::-webkit-scrollbar { display: none }`); the board caps its size by the viewport height left over (`max-width: calc(100dvh - 276px)` — 300px before the footer lost its second row), so short screens trade board pixels for list room instead of overflowing. The floating letter keyboard clamps its vertical position above the pinned footer (`Keyboard.tsx`). The full-height column is flex all the way through — `body → #root → .context` (`min-height: 0` on the links below `body` on phones): `#root` was the missing link in the first cut, a plain auto-height block that cut the column and left the footer floating mid-page; at every width the footer also sits at the bottom of the page (`margin-top: auto`), not right after the content. **The landscape-tablet layout (wider than tall and no taller than 1024px — the height cap is what tells a sideways tablet from a desktop monitor, since even the 12.9" iPad stands exactly 1024px tall in landscape while monitors are 1080px and up; an earlier `max-width: 1024px` cap missed most tablets outright, 1080–1366px held sideways; its own media query after the phones one)** moves the two score columns out to the sides of the board: `.context` becomes a three-column grid (`words | board | words`) whose children are placed by `grid-area`, and `.score-panel`/`.score-columns` are `display: contents` so the two columns that stack side by side elsewhere become items of that outer grid — no wrapper was added to the JSX. A tablet held upright has the height rather than the width to spare, so the `orientation: landscape` half of the query leaves a portrait one to the app-shell query above, which stacks the lists under the board and gives them the phone's chip rows and in-column scrolling. That shell query is deliberately **not** the 560px `Keyboard.tsx` matches: the letter keyboard keeps floating at its cell on a tablet of either orientation, its full-screen-width form staying on the phone-only `max-width: 560px` rule for `.keyboard-panel` — the one exception being the landscape phone below. The board (and with it the floating letter keyboard, which Keyboard.tsx clamps into the board column) is capped by the `--tablet-board` variable the query sets on `.context` — `min(520px, 52vw, 100dvh - 230px)`, the height term because a sideways tablet is short and an uncapped board would push the footer off a 600px-tall screen — and each side column is capped to the same height and scrolls its list inside, so the board and the controls row never move as words accumulate. The word rows take the phone's chip form there (framed, 36px, the whole row the tap target); the computer's column drops its right-alignment mirroring — that faced the two lists across a shared center line when they sat under the board, and at the screen's edges it only pushed the bot's words away from it. **A landscape phone (wider than 560px and under 500px tall — its own query after the landscape-tablet one) keeps that three-column grid but compacts the chrome to its ~400px of height**, which the tablet layout was never sized for: the tablet's 230px reserve left the board a ~130px stamp, so the status row, the controls row and the footer each slim down and the reserve drops to `100dvh - 150px` (minus the bottom safe-area inset); the controls row leaves the board column and spans the full width — on the board-width row the centered «Слово 7 из 21» collided with «Заново»/«Отмена»; the middle grid row becomes `minmax(0, 1fr)` with the board and the columns centered in it (the footer keeps the bottom edge), the shell stops scrolling like the portrait phone's, and the score rows shorten to 30px chips to fit more of the list beside the board. The letter keyboard takes the phone's full-width pinned form there too — `Keyboard.tsx` matches this query as `SHORT_LANDSCAPE`, because board-width keys would be ~16px.

The fullscreen phone experience goes through installation, not the browser tab: a page cannot hide the address bar itself (and the app shell does not scroll, which is what usually collapses the bar), so the site ships a web app manifest (`public/manifest.webmanifest`, `display: "standalone"`, relative `start_url`/`scope` and icon paths — subpath-deployable on GitHub Pages) plus the iOS standalone metas in `index.html`. Added to the home screen, the game launches without any browser UI; the manifest icons (`icon-192/512.png`, full-bleed) are generated by `scripts/icon.py` together with the rest of the icon set — the design is the wood board (the app's outward identity; independent of the in-page default theme), and `theme-color` in `index.html` plus the manifest's `theme_color`/`background_color` match it (`#8a5a2b`) — that pair is the launch color; once the app runs, App re-points the page's `meta theme-color` tags (shipped as light/dark media variants, see the Board themes note) at the active theme (the `chrome` field in `THEMES`, the top edge of the theme's page background), because the manifest value is read at launch and cannot change — without this the installed app's status bar stays wood whatever theme is picked.

17. An English word opens a translation popup instead of following its link: tapping an English word in a score list or the bot's word in the status line (both are buttons there — an action, not navigation) shows a compact centered modal (`WordPopup.tsx`, the same substrate as the rules modal; closed by the quiet ✕, a backdrop click or Escape) with the word, a muted part-of-speech marker, its IPA transcription and the Russian translations from the bundled data (`game/translate-en.ts`, ~13.5k of the 15.3k words translated, ~15k transcribed; a word with neither shows a quiet «no translation» line instead), and below them the same Yandex Translate link the word itself used to follow — the quick glance is bundled, the full lookup stays one tap away. The card is slightly translucent and frosted (`color-mix` of `--card-bg` at 88% + `backdrop-filter` blur), so the board with the tapped word's track (see 13) keeps faintly showing through. Russian words keep their direct gramota.ru links. The marker reads «сущ.» — the dictionary is nouns — but follows the sense that actually supplied the translations: a word the noun sources miss is often translated only as an adjective, verb or adverb («прил.», «глаг.», «нареч.»; 370/153/14 words), and the data records that per word. The data is generated by `scripts/translate-en.mjs`: IPA from ipa-dict en_US (MIT), translations from OpenRussian nouns reversed by their English glosses (CC-BY-SA 4.0 — both sources describe noun senses, matching the dictionary's nouns-only filter), the gaps of each filled from the ru.wiktionary entries of the English words themselves (their «Значение» lines are the Russian equivalents — the noun blocks first, then the adjective/verb/adverb ones) and whatever still remains from the English Wiktionary's translation tables (`{{t|ru|…}}`) of the same sections; the fetched wikitext of both wiktionaries is cached in `.tmp-translate/`.

18. Game history: finished games are archived the moment they end — an App effect keyed on the phase calls `addGame` (`state/history.ts`) on every transition into `over`, the computer's closing word included (StrictMode's double run and the re-fire on loading an archived game back are absorbed by the duplicate check on the language + played words, since the starting word is random). The archive lives in localStorage under `balda-history`: a versioned wrapper, each entry shape-checked on read (a corrupt entry is dropped on read and disappears for good at the next archive or removal), the 100 newest kept (`MAX_GAMES`); an entry holds the saved-game snapshot's fields plus the finish timestamp. The footer's clock button (one of the four `.footer-btn` buttons; the clock is an inline SVG in `currentColor` so it follows the theme — an emoji clock cannot be recolored) opens `HistoryModal.tsx` — the rules modal's substrate, newest first; a row shows the outcome (short «Победа»/«Поражение»/«Ничья» labels — the end panel's phrases are too long), the final score, the language label and the finish date in the UI language's locale. A tap loads the game back: `entryToState` + the `LOAD_GAME` action restore the board, the word lists, the tracks and the `over` phase (the end panel reopens; the save effect overwrites `balda-game`, so the loaded game simply becomes the current game — «Заново» and a language switch treat it like any other), and the UI language follows the entry's language the way the new-game modal's start pairs them. Loading over a game in progress (words played and not finished — the new-game modal's start-confirmation criterion) asks first: the row's two-tap armed confirmation («Точно?», the tooltip warns the current game will be lost, 3 s disarm) — a finished current game needs none, it is already in the history. Each row also carries a ⋮ button (`.history-more`, an inline-SVG glyph in `currentColor`) opening a small actions menu — a fixed-position mini card placed at the tapped dots' viewport coordinates (the card scrolls, an in-card menu would be clipped by its overflow; it flips above the dots at the viewport's bottom edge) over a transparent click-away layer whose stopped click keeps the substrate's own click from closing the modal, and a capture-phase Escape listener that closes only the menu ahead of App's window handler. Its one action so far is «Удалить» — `removeGame(at)` drops the entry and the list re-reads; a scroll of the card dismisses the menu too. The row is a div carrying the chip frame, split into the `.history-load` button (the tap target proper) and the ⋮ — buttons cannot nest.

19. The footer is a single row of four buttons in the standard mobile tab-bar look — the icon over a small caption, no circles or frames (plus/clock/«?»/gear; the icons are inline SVG strokes in `currentColor` — the clock's reasoning — normalized to one 20px box with the "?" glyph, the captions are `texts.footer.*`), each opening its modal: the new-game sheet, the history, the rules and the settings. The new-game modal (`NewGameModal.tsx`) holds the game language and the bot difficulty over a full-width start button: the language is a plain selection until the button applies it (and restarts the game in it — App's `startGame`), the difficulty applies at once — it only steers the computer's next move and survives closing the sheet without starting. Over a game in progress (a word played beyond the starting one) the start button arms to «Точно?» for 3 s — the old LangPicker's two-tap confirmation moved onto the button, and the LangPicker itself is gone. The settings modal (`SettingsModal.tsx`) holds the theme picker, restyled from the footer's bare swatch row into cards — the swatch over the localized name, the active theme outlined; the cards live in the modal, so their quiet frame mixes with the card's own text color. Both modals share the `.modal-card`/`.modal-head`/`.modal-close` substrate of the rules/history cards, with small uppercase `.modal-label` captions over the picker groups, and close on ✕, a backdrop click or Escape (App's keydown chain gained the two new overlays ahead of the rules modal). The old two-row footer (language + difficulty segments, then «?», the clock and the swatches) is gone with them: the captioned-button row pins to the phone's bottom edge with the buttons spread across the width (flex 1, capped at 110px), the body's bottom reserve drops from 88px to 64px, and the board's height share grows by the difference (300px → 276px of the viewport).
